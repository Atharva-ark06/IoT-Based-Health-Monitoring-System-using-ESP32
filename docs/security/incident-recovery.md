# Incident Recovery Checklist

- [ ] Root cause and affected assets are documented.
- [ ] Compromised secrets are revoked or rotated.
- [ ] Application image and configuration are reviewed before restoring service.
- [ ] Database integrity is checked and restore source is verified.
- [ ] Synthetic ingestion and authenticated retrieval are tested.
- [ ] Security headers, TLS termination, and access controls are rechecked.
- [ ] Monitoring is increased for a defined period.
- [ ] Follow-up work has owners and due dates.

Recovery is not complete until the incident lead records the decision and remaining risks.
